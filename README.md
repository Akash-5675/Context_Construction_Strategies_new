# Context Construction Strategies for Biomedical RAG

**Student:** Akash Ramesh (AM.SC.P2AML25002) | **Guide:** Dr. Aswathy Mohan

This project measures how chunking choices affect retrieval and answers in a
Retrieval-Augmented Generation (RAG) pipeline on PubMed abstracts.

## Experiment

| Factor | Levels |
|---|---|
| Chunking conditions | 15: fixed size 128/256/512 words x 0/10/20/40% overlap, NLTK sentences, scispaCy sentences, semantic |
| Questions | 100 (20 each for hypertension, type 2 diabetes, lung cancer, COVID-19, Alzheimer's) |
| Retrieval depth k | 3, 5, 8, 10 |
| Embedding models | all-MiniLM-L6-v2, NeuML/pubmedbert-base-embeddings |

**Total:** 15 x 100 x 4 x 2 = **12,000 runs**, using 981 abstracts.

Answers were generated by Llama 3.1 8B (Ollama, Q4_K_M, temperature 0, seed 42) on
Kaggle's two T4 GPUs. Search uses exact cosine similarity (FAISS `IndexFlatIP`).

## Quick start

Python 3.12 is recommended.

```bash
pip install -r requirements.txt
```

| Command | What it shows |
|---|---|
| `python main.py status` | Whether all required files are present |
| `python main.py validate` | Data-quality checks on all 12,000 runs |
| `python main.py results` | Results by condition, k and embedding model |
| `python main.py demo` | One question through retrieval, saved answer and scores |
| `python main.py analyze` | Regenerates statistics, tables and figures |

`demo` and `analyze` download the embedding models on first use. Try another run with:

```bash
python main.py demo --question DIA_001 --condition semantic --encoder minilm --k 3
```

## Rebuilding from scratch

Each stage reuses saved outputs. Delete an output to rebuild it.

```bash
python src/collect.py
python src/run_chunkers.py
python pipeline/indexer.py
```

Corpus collection needs internet access and an `ENTREZ_EMAIL` in `.env`. It returns
PubMed's current records, so a new corpus can differ from the saved one. The semantic
and scispaCy chunkers need `en_core_sci_sm` (see `requirements.txt`).

The full run needs GPUs: see `kaggle/rag_rerun.ipynb`. It took about 4.2 hours.
For a small local test with Ollama running:

```bash
python src/experiment_runner.py --part A --max-runs 5 --results results/test_run.csv
```

## Metrics

| Metric | Meaning |
|---|---|
| `rouge_l` | Longest-common-subsequence F1 against the reference answer |
| `answer_relevance` | Cosine similarity between question and answer |
| `faithfulness` | Share of distinct answer words that appear in the retrieved chunks |
| `retrieval_recall` | Whether a chunk from the gold abstract was retrieved |
| `evidence_coverage`, `evidence_hit` | Whether retrieved chunks contain the evidence text |
| `answered` | Whether the model gave an answer rather than a refusal |

## Main results

Hypothesis tests use one mean per question or question-level mixed models.

| Hypothesis | Result |
|---|---|
| H1: overlap gives no benefit | Mostly supported: no individual comparison is significant, but the mixed model gives p = 0.041, with small differences favouring overlap at 128 and 256 words |
| H2: sentence matches semantic chunking | Not supported: mean ROUGE-L is 0.555 for sentence chunking and 0.325 for semantic chunking at threshold 0.75 |
| H3: quality declines past about 2,500 tokens | Partly supported: the slope turns negative, but mean ROUGE-L only falls from about 0.56 to 0.54 |

PubMedBERT scored higher than MiniLM (ROUGE-L 0.547 vs 0.526). Full output is in
`results/analysis/robust_stats.txt`.

## Limitations

- NLTK and scispaCy chunks are about 97% identical, so similar scores are expected.
- Abstracts average 238 words, so overlap can change little at 512 words.
- Semantic chunks average 23 words, so semantic runs receive much less context.
- Reference answers use their source abstracts' wording, which may inflate ROUGE-L.
- 254 abstracts contain HTML tags such as `<i>`, kept as they came from PubMed.
- Prompt and completion token counts were not recorded and remain 0 in the results.
- Questions were drafted with AI assistance, then checked against their source abstracts.
